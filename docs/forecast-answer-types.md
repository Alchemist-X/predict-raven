# 按问题保留答案形式

[English](en/forecast-answer-types.md)

预测入口先判断用户要什么答案，再冻结时间、选项、单位和判断标准。不会把四选一、分数或公司比较改写成任意一个二元事件。

| 问法 | `answerType` | 答案 |
| --- | --- | --- |
| 某家公司是否削减预算 | `binary` | 保留原有概率、证据和报告 |
| 四个互斥且穷尽的选项哪一个发生 | `categorical` | 所有选项的概率、首选或并列；总和为 1 |
| 下季收入增速、某量表分数 | `numeric` | 点估计、单位、模型范围；分数必须有上下限与评分规则 |
| M7 谁最可能下调资本开支 | `independent_ranking` | 每家公司该事件的边际概率及完整排名；不归一化 |

独立排名只表示事件分别判断，不假设公司决策在统计上互不相关。“最可能发生”不是“谁最早发生”；几家公司可能同时发生，也可能都不发生。没有指引或没有找到材料属于信息缺口，不等于概率为零。

## 调用

自然语言自动判断是默认行为。需要冻结结构时，CLI 可传 `--answer-request` JSON；API/MCP 的 `answerRequest` 使用相同字段：`answerType`、`options`（`id`/`label`）、`unit`、`minimum`、`maximum`、`resolution`。

```bash
pnpm forecast:event -- "谁会赢得四选一比赛？" --answer-request '{"answerType":"categorical","options":[{"id":"a","label":"A"},{"id":"b","label":"B"},{"id":"c","label":"C"},{"id":"d","label":"D"}]}'
pnpm forecast:event -- "下一季质量评测会得到多少分？" --answer-request '{"answerType":"numeric","unit":"points","minimum":0,"maximum":100,"resolution":"按下一季公开评测的既定百分制规则结算。"}'
pnpm forecast:event -- "M7公司中哪家最有可能在未来半年里下调capex" --max-rounds 2
```

指定的选项、单位、范围和事件标准在审题复核后仍须保留。相同题目但不同选项、单位或标准具有不同运行 ID，避免错误恢复旧结果。原有不带新参数的二元 ID 不变。

## 引擎与展示

`question-spec.ts` 负责分类、审题及校验；`answer-math.ts` 负责更新数值；`structured-engine.ts` 负责研究、来源记录、去重、持久化和恢复。模型提出有原文引用的原子事实及影响，引擎计算最终答案，最后的说明阶段不能覆盖数值。

分类概率按证据似然更新后统一归一化；公司排名分别更新各自概率；数值预测使用正态分布的精度更新。来源重复按信息组折减，未在成功检索记录中找到的 URL 不影响数值。模型给出的起点、影响程度和数值信号仍是主观估计，不能宣称已完成概率校准。数值范围是模型假设下的 10–90 分位范围，并受量表边界限制，不是历史验证的置信区间。

新状态使用 `schemaVersion: 2` 与 `answer`，没有 `currentProb`。旧 `loadState` 只返回二元状态；通用 API/UI 按类型读状态。JSON、文本、PDF、研究页与详情页分别展示完整分布、数值或排名，不套用二元图表。恢复时重放证据并核对各轮答案；已完成相同轮数的恢复不会再次调用模型或检索。

## 扩展资源库

Geoscope / Signal Desk 对读者统一称 **扩展资源库**，底层 `signal_desk_*` 标识保持兼容。个人研究入口强制设置 `FORECAST_REQUIRE_EXPANDED_LIBRARY=1` 和 `FORECAST_SIGNAL_DESK=1`。公开仓库不包含订阅权限或正文；其他环境须自行接入个人网关。

二元问题和新类型均在研究阶段先执行真实关键词检索、分段读取。比较题覆盖每个候选。每篇预读材料都必须以匹配的文章 ID、URL 和准确短引句进入证据，或附具体的不采用理由。材料无法取得时记录失败和缺口，不伪装成无结果的成功检索。搜索结果不等于原文、摘要不等于 PDF、作者判断不等于公司指引。引用时注明原作者、发表日期与材料性质。

关键边界：当库被要求但网关未启用时直接报错；已启用但上游报错时保存实际尝试并明确覆盖缺口。个人原文片段与失败模型响应仅保存到私人运行目录，通用接口不输出整篇原文。详见[接入说明](signal-desk-research.md)。

## 验收重点

应同时验证：原有二元回归、四选一加总、排名不加总、数值单位/负数/量表、并列、错误输出重试、来源记录保留、跨轮去重、恢复重放、强制资源库引用或解释，以及 API/MCP/网页/PDF 的真实呈现。对实际预测另做来源日期、公司数字归属和事件定义核对。技术测试证明执行行为，不证明未来预测正确。

失败输出保留到每轮 attempt 文件。恢复被拒绝的轮次时，先重用已保存的检索记录，只调用一次禁用工具的格式修正；旧 attempt 单独归档。说明阶段失败可以单独恢复，已完成的证据不会重复赋权。子进程按 UTF-8 连续解码，避免中文跨数据块被截坏。
